\chapter{Options \& Variables}

	\rpgtex{} defines many dozens to hundreds of variables, most with the (expl3) syntax \cmd*{__rpg\_[x]}. Most of these are used in the internal functioning of the macros, however a number of them are useful for a user to understand.


	\section{Package Options}\label{S:PackageOptions}
		Whether \rpgtex{} is loaded directly as a package or indirectly through one of its classes, options may be passed to it which change the behaviour of the resulting document:
		\begin{Code}
			\textbackslash{}documentclass[<options>]\{rpgbook\}

			\textbackslash{}usepackage[<options>]\{rpgtex\}
		\end{Code}
		Each option takes one of two forms:

		\begin{description}
			\item[Key-value options:] The name of the option is followed by an equals sign and a value:
			      \begin{Code}
				      \textbackslash{}usepackage[columns = 2, bg = print]\{rpgtex\}
			      \end{Code}
			\item[Flags:] Only the name of the option is provided. Its presence enables the associated behaviour:
			      \begin{Code}
				      \textbackslash{}usepackage[openright]\{rpgtex\}
			      \end{Code}
		\end{description}

		The available options are:

		\RpgFlag{background}{
			If present, activates the `paper background' modules, including the background colour, paper images, geometry overloads and footer changes.

			This flag is set by default when loading a class, but must be passed explicitly to enable these modules when loading the package directly.
		}
		\RpgKeyval{bg}{= full / print / none}
		{
			Controls the behaviour of the background and footer decorations. The value must be one of the three listed above, else an error is thrown. The default value is \texttt{full}.

			The most visible effect of this option is to control whether the `background paper' set by \cmdref{RpgThemeSetPaper} and \cmdref{RpgThemeBackgroundColor}, and the footer decorations set by \cmdref{RpgThemeFooterDecoration}, appear in the document:

			\begin{center}
				\begin{tabular}{rcc}
					Value          & Paper  & Footer Decorations
					\\
					\texttt{full}  & \cmark & \cmark
					\\
					\texttt{print} & \xmark & \cmark
					\\
					\texttt{none}  & \xmark & \xmark
				\end{tabular}
			\end{center}

			This option also changes the behaviour of the rpgcard class \RpgPage[p]{S:cardClass}, and other environments may similarly alter their colours or layouts in response to its value.
		}
		\RpgKeyval{columns}{= 1 / 2}
		{
			Places the document into either \texttt{onecolumn} or \texttt{twocolumn} mode. The default value is \texttt{2}.

			More advanced column layouts require the user to manually use the \texttt{multicols} environment.
		}
		\RpgFlag{font}{
			If present, activates the font modules, applying the package fonts wherever possible.

			This flag is set by default when loading a class, but must be passed explicitly to enable these modules when loading the package directly.
		}
		\RpgFlag{justified}
		{
			If present, sets the text to be justified throughout the document. By default, text is left-aligned (`ragged right').
		}
		\RpgFlag{noemph}{
			If present, the default behaviour of \cmd{emph} is left unchanged. By default, \cmd{emph} is redefined to be an alias of \cmdref{RpgKey}.
		}
		\RpgFlag{nomultitoc}{
			If present, disables the multi-column table of contents.
		}
		\RpgFlag{oneside}{
			If present, places the document into one-sided mode. This disables alternating footers, but allows for consistent asymmetric margins (as in this document, where the left margin is enlarged to accommodate macro names).
		}
		\RpgFlag{openright}{
			If present, places the document into right-opening mode, such that chapters always begin on a right-hand page. By default, chapters may begin on any page (see the documentation of the \texttt{book} class for more details).
		}
		\RpgFlag{sections}{
			If present, activates the sections modules, including the part-page overloads and any theme behaviour which modifies the section commands.

			This flag is set by default when loading a class, but must be passed explicitly to enable these modules when loading the package directly.
		}
		\RpgKeyval{size}{= <font-size>pt}
		{
			Sets the base font size of the document, if permitted by the parent class. The default value is \texttt{10pt}.

			The allowed values depend on the class being used (see the class section, beginning on \RpgPage{S:bookClass}).
		}
		\RpgKeyval{theme}{= <theme name>}
		{
			The initial value passed to \cmdref{RpgSetTheme} once package initialisation is complete.

			The default value is \texttt{default}, which activates the Default Theme \RpgPage[p]{Theme:Default}.
		}
		\RpgKeyval{themepath}{= </path/to/themes/>}
		{
			Calls \cmdref{RpgSetThemePath} before the theme is loaded, allowing custom themes to be used.

			The default value is \cmd{RpgPackagePath}\texttt{/themes}, with the assumption that a theme called \texttt{name} is stored in \texttt{themes/name/name.cfg}.
		}
		\RpgFlag{title}{
			If present, activates the titling module and any theme presets which alter the behaviour of \cmd{maketitle}.

			This flag is set by default when loading a class, but must be passed explicitly to enable this module when loading the package directly.
		}
	\section{Colo(u)rs}\label{S:Colors}

		\rpgtex{} defines a number of named colours\footnote{Although this document uses British spelling, the colour names follow the American spelling used throughout \LaTeX{} and \texttt{xcolor}, and must be written exactly as given (including capitalisation).} which are used by its various elements. The default values listed below may be overridden by the active theme.

		\subsection*{Co-varying Colours}

			The following colours are coupled together, and by default all take the same value:
			\begin{description}
				\item[\texttt{ThemeColor}] A general-purpose colour from which the other co-varying colours inherit. Default: \texttt{white!60!black}.
				\item[\texttt{SidebarColor}] The background colour of the \envref{RpgSidebar} environment.
				\item[\texttt{TableColor}] The background colour of alternate rows in an \envref{RpgTable}.
				\item[\texttt{TipColor}] The background colour of the \envref{RpgTip} environment.
			\end{description}

			Calling \cmdref{RpgSetThemeColor} assigns a new value to \texttt{ThemeColor} and all three co-varying colours simultaneously:
			\begin{Code}
				\cmd{RpgSetThemeColor}\{blue!20!white\}
			\end{Code}

		\subsection*{Independent Colours}

			The remaining colours are set individually:
			\begin{description}
				\item[\texttt{ContourInnerColor}] The default colour of the inner text produced by \cmdref{RpgContour}. Default: \texttt{black}.
				\item[\texttt{ContourOuterColor}] The default colour of the outer contour drawn around text by \cmdref{RpgContour}. Default: \texttt{white!50!black}.
				\item[\texttt{FiligreeBackColor}] The background colour of the \envref{RpgFiligree} environment. Default: \texttt{white}.
				\item[\texttt{FiligreeColor}] The colour used to draw the filigree frame applied by the \texttt{rpgfiligree} style. Default: \texttt{black}.
				\item[\texttt{NarrationColor}] The background colour of the \envref{RpgNarration} environment. Default: \texttt{F7F2E5} (HTML).
				\item[\texttt{PaperColor}] The background colour of each page, applied only when the paper background is enabled (see the \texttt{bg} option, \RpgPage{S:PackageOptions}). Default: \texttt{white}.
				\item[\texttt{SecretColor}] The default frame colour of the \envref{RpgSecret} environment. Default: \texttt{black!30!white}.
			\end{description}

			Any of these colours, including the co-varying colours, may be modified individually using the standard \texttt{xcolor} interface:
			\begin{Code}
				\cmd{definecolor}\{NarrationColor\}\{HTML\}\{FFFFFF\}

				\cmd{colorlet}\{SidebarColor\}\{red!10!white\}
			\end{Code}
			Modifying a co-varying colour in this way changes only that colour, leaving the others unaffected.
	\section{Section Names}\label{S:SectionNames}

		Many themes customise their appearance beyond the simple use of \texttt{mark}s (such as \cmd{chaptermark}). To support this, \rpgtex{} provides direct access to the names of the current chapter, section, subsection and subsubsection.

		\begin{RpgSidebar}{Sections Mode Only}
			These names are recorded by redefining standard \LaTeX{} commands, and are therefore only available in \emph{sections mode}. Sections mode is enabled by default when using one of the \rpgtex{} classes, and may otherwise be enabled by passing the \texttt{sections} option to the package \RpgPage[p]{S:PackageOptions}.

			When active, sections mode:
			\begin{itemize}
				\item Redefines \cmd{chaptermark}, \cmd{sectionmark}, \cmd{subsectionmark} and \cmd{subsubsectionmark} so that, in addition to their usual behaviour, they store the name they are given in the variables below.
				\item Sets \texttt{secnumdepth} to \texttt{0}, so that sections and their subdivisions are unnumbered.
				\item Replaces \cmd{part} with a version which draws a full-page part page using the active theme. The starred form, \cmd{part*}, falls back to the original \LaTeX{} command.
			\end{itemize}
			Themes may additionally alter the formatting of the sectioning commands when sections mode is active.
		\end{RpgSidebar}


		Each of the following variables is initially blank, and holds its value until the next command of the same level is called: beginning a new chapter does not, for example, reset \cmd{RpgSectionName}.

		\RpgVariable{RpgPartName}{The name given to the last \cmd{part} command.}
		\RpgVariable{RpgChapterName}{The name given to the last \cmd{chapter} command, or set by calling \cmd{chaptermark}}
		\RpgVariable{RpgSectionName}{The name given to the last \cmd{section} command, or set by calling \cmd{sectionmark}. Starred sections (\cmd{section*}) do not update this value.}
		\RpgVariable{RpgSubsectionName}{The name given to the last \cmd{subsection} command, or set by calling \cmd{subsectionmark}. Starred subsections (\cmd{subsection*}) do not update this value.}
		\RpgVariable{RpgSubsubsectionName}{The name given to the last \cmd{subsubsection} command, or set by calling \cmd{subsubsectionmark}. Starred subsubsections (\cmd{subsubsection*}) do not update this value.}


		\RpgFunction{RpgGetName}{\param{part / chapter / section / subsection / subsubsection}}
		{
			Returns the name stored for the given level (equivalent to the corresponding variable above). Any other input results in an error.

			Since these names (other than that of the part) are taken from the \texttt{mark} commands, they may be set manually, without creating a new heading, by calling the relevant \texttt{mark} command directly.
		}

		\RpgFunction{RpgFake}{\param{level}\param{name}}
		{
			Mimics the creation of a new heading at the given \texttt{level} without printing a heading in the document. Specifically, it:
			\begin{itemize}
				\item Adds an entry called \texttt{name} to the table of contents at the given level, with a hyperlink anchor at the current position.
				\item Updates the stored name for that level, as if a real heading had been created. For \texttt{chapter} to \texttt{subsubsection} this is done by calling the corresponding \texttt{mark} command, so any running headers are also updated.
			\end{itemize}
			The \texttt{level} must be one of \texttt{part}, \texttt{chapter}, \texttt{section}, \texttt{subsection} or \texttt{subsubsection}. Any other value results in an error.
		}

		\RpgGetExample{section-names}

	\section{Command Line Interface}\label{S:CMD}

		By default, \LaTeX{} does not have a `command line interface' which allows a user to modify the document from within the command line: changes to the document have to be placed inside the file, and then compiled. However, we found that -- particularly with the \textit{print} option (which suppresses background images on the paper, reducing ink requirements for printing), it was convenient to be able to compile the same document in either `normal' mode, or `print mode', without modifying the text.
		%
		% 	To this end, we have provided a method for pseudo-`command line variables' to be inserted into the RpgOptions module. To do this, we exploit the fact that \TeX{} can read documents from an input stream, not just files.
		%
		%
		% 	\RpgMacro{RpgCMD}{}{Holds key-value pairs to be inserted into RptOptions after the standard parsing is run, ideal for command line modification.}
		% 	{
		% 	xelatex ``\bs{}def\bs{}RpgCMD{<rpg-options>} \bs{}input{<document>}''
		% 	}{
		% 	This will compile the \texttt{<document>}, with the contents of \texttt{RpgCMD} parsed as if they had been placed into \texttt{\bs{}documentclass[<rpg-options>]{rpgclass}} or when invoking the package: \texttt{\bs{}usepackage[rpg-options]{rpgtex}}.
		%
		% 	Values passed to \texttt{RpgCMD} will override values passed to the package the standard way.
		%
		% 	The \texttt{rpgtex} compiler which we have provided \RpgPage[p]{C:Compiler} performs this insertion by default for several predefined variables:
		%
		% 	\begin{minipage}{0.3\linewidth}
		% 		\begin{Code}
		% 			\centering rpgtex document.tex -p
		% 		\end{Code}
		% 	\end{minipage}~~aliases~~\begin{minipage}{0.6\linewidth}
		% 		\begin{Code}
		% 			\centering xelatex "\bs{}def\bs{}RpgCMD{bg=print} \bs{}input document.tex"
		% 		\end{Code}
		% 	\end{minipage}
		%
		% 	Thereby allowing the user to switch between \texttt{print} and \texttt{full} mode with a compiler switch.
		% 	}
