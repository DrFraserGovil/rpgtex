\chapter{Options \& Configuration}

	This chapter describes the ways in which the behaviour of \rpgtex{} may be configured without writing any new code: the options which may be passed to the package or class, the named colours used by its elements, and the command line interface for changing these options at compile time.


	\section{Package Options}\label{S:PackageOptions}
		Whether \rpgtex{} is loaded directly as a package or indirectly through one of its classes, options may be passed to it which change the behaviour of the resulting document:
		\begin{Code}
			\textbackslash{}documentclass[<options>]\{rpgbook\}

			\textbackslash{}usepackage[<options>]\{rpgtex\}
		\end{Code}
		Each option takes one of two forms:

		\begin{description}
			\item[Key-value options:] The name of the option is followed by an equals sign and a value:
			      \begin{Code}
				      \textbackslash{}usepackage[bg = print, theme = dnd]\{rpgtex\}
			      \end{Code}
			\item[Flags:] Only the name of the option is provided. Its presence enables the associated behaviour:
			      \begin{Code}
				      \textbackslash{}usepackage[justified]\{rpgtex\}
			      \end{Code}
		\end{description}

		The available options are:

		\RpgFlag{background}{
			If present, activates the `paper background' modules, which control the paper colour and background images, the footer decorations, and the spacing around floats.

			This flag is set by default when loading a class, but must be passed explicitly to enable these modules when loading the package directly.
		}
		\RpgKeyval{bg}{= full / print / none}
		{
			Controls the behaviour of the background and footer decorations. The value must be one of the three listed above, else an error is thrown. The default value is \texttt{full}.

			The most visible effect of this option is to control whether the `background paper' set by \cmdref{RpgThemePaperImage} and \cmdref{RpgThemePaperColor}, and the footer decorations set by \cmdref{RpgThemeFooterDecoration}, appear in the document:

			\begin{center}
				\begin{tabular}{rcc}
					Value          & Paper  & Footer Decorations
					\\
					\texttt{full}  & \cmark & \cmark
					\\
					\texttt{print} & \xmark & \cmark
					\\
					\texttt{none}  & \xmark & \xmark
				\end{tabular}
			\end{center}

			This option also changes the behaviour of the rpgcard class \RpgPage[p]{S:cardClass}, and other environments may similarly alter their colours or layouts in response to its value.
		}
		\RpgKeyval{columns}{= 1 / 2}
		{
			Places the document into either \texttt{onecolumn} or \texttt{twocolumn} mode. The default value is \texttt{2}.

			More advanced column layouts require the user to manually use the \texttt{multicols} environment.

			This option only has an effect when using one of the \rpgtex{} classes.
		}
		\RpgFlag{font}{
			If present, activates the font modules, applying the package fonts wherever possible.

			This flag is set by default when loading a class, but must be passed explicitly to enable these modules when loading the package directly.
		}
		\RpgFlag{justified}
		{
			If present, sets the text to be justified throughout the document. By default, text is left-aligned (`ragged right').
		}
		\RpgFlag{noemph}{
			If present, the default behaviour of \cmd{emph} is left unchanged. By default, \cmd{emph} is redefined to be an alias of \cmdref{RpgKey}.
		}
		\RpgFlag{nomultitoc}{
			If present, disables the multi-column table of contents.
		}
		\RpgFlag{oneside}{
			If present, places the document into one-sided mode. This disables alternating footers, but allows for consistent asymmetric margins (as in this document, where the left margin is enlarged to accommodate macro names).

			This option only has an effect when using one of the \rpgtex{} classes.
		}
		\RpgFlag{openright}{
			If present, places the document into right-opening mode, such that chapters always begin on a right-hand page. By default, chapters may begin on any page (see the documentation of the \texttt{book} class for more details).

			This option only has an effect when using one of the \rpgtex{} classes.
		}
		\RpgFlag{sections}{
			If present, activates the sections modules, including the part-page overloads and any theme behaviour which modifies the section commands.

			This flag is set by default when loading a class, but must be passed explicitly to enable these modules when loading the package directly.
		}
		\RpgKeyval{size}{= <font-size>pt}
		{
			Sets the base font size of the document, if permitted by the parent class. The default value is \texttt{10pt}.

			This option only has an effect when using one of the \rpgtex{} classes.

			The allowed values depend on the class being used (see the class section, beginning on \RpgPage{S:bookClass}).
		}
		\RpgKeyval{theme}{= <theme name>}
		{
			The initial value passed to \cmdref{RpgSetTheme} once package initialisation is complete.

			The default value is \texttt{default}, which activates the Default Theme \RpgPage[p]{Theme:Default}.
		}
		\RpgKeyval{themepath}{= </path/to/themes/>}
		{ \label{S:ThemePath}
			Calls \cmdref{RpgSetThemePath} before the theme is loaded, allowing custom themes to be used.

			The default value is \texttt{themes}, which \TeX{} locates within the \rpgtex{} installation. A theme called \texttt{name} is then expected to be stored in \texttt{<themepath>/name/name.cfg}.
		}
		\RpgFlag{title}{
			If present, activates the titling module and any theme presets which alter the behaviour of \cmd{maketitle}.

			This flag is set by default when loading a class, but must be passed explicitly to enable this module when loading the package directly.
		}
	\section{Colors}\label{S:Colors}

		\rpgtex{} defines a number of named colors which are used by its various elements. The default values listed below may be overridden by the active theme.

		\begin{RpgSidebar}{A Note on Spelling}
			Although this document otherwise uses British spelling, this section follows the American spelling of `color' used throughout \LaTeX{} and \texttt{xcolor}. The color names below must be written exactly as given, including their spelling and capitalization.

			An exception is in Gray/Grey, as I personally cannot remember which is the `right' way to spell it, so I have aliased most colours to use both spellings.
		\end{RpgSidebar}

		\subsection*{Co-varying Colors}

			The following colors are coupled together, and by default all take the same value:
			\begin{RpgTable}{lXl}
				Color & Usage & Default
				\\
				\texttt{SidebarColor} & The background color of the \envref{RpgSidebar} environment. & \texttt{ThemeColor}
				\\
				\texttt{TableColor} & The background color of alternate rows in an \envref{RpgTable}. & \texttt{ThemeColor}
				\\
				\texttt{ThemeColor} & A general-purpose color from which the other co-varying colors inherit. & \texttt{white!60!black}
				\\
				\texttt{TipColor} & The background color of the \envref{RpgTip} environment. & \texttt{ThemeColor}
			\end{RpgTable}

			Calling \cmdref{RpgSetThemeColor} assigns a new value to \texttt{ThemeColor} and all three co-varying colors simultaneously:
			\begin{Code}
				\cmd{RpgSetThemeColor}\{blue!20!white\}
			\end{Code}
		\subsection*{Independent Colors}

			The remaining colors are set individually:
			\begin{RpgTable}{lXl}
				Color & Usage & Default
				\\
				\texttt{ContourInnerColor} & The default color of the inner text produced by \cmdref{RpgContour}. & \texttt{black}
				\\
				\texttt{ContourOuterColor} & The default color of the outer contour drawn around text by \cmdref{RpgContour}. & \texttt{white!50!black}
				\\
				\texttt{FiligreeBackColor} & The background color of the \envref{RpgFiligree} environment. & \texttt{white}
				\\
				\texttt{FiligreeColor} & The color used to draw the filigree frame applied by the \texttt{rpgfiligree} style. & \texttt{black}
				\\
				\texttt{NarrationColor} & The background color of the \envref{RpgNarration} environment. & \texttt{F7F2E5} (HTML)
				\\
				\texttt{PaperColor} & The background color of each page, applied only when the paper background is enabled (see the \texttt{bg} option, \RpgPage{S:PackageOptions}). & \texttt{white}
				\\
				\texttt{SecretColor} & The default frame color of the \envref{RpgSecret} environment. & \texttt{black!30!white}
			\end{RpgTable}

			Any of these colors, including the co-varying colors, may be modified individually using the standard \texttt{xcolor} interface:
			\begin{Code}
				\cmd{definecolor}\{NarrationColor\}\{HTML\}\{FFFFFF\}

				\cmd{colorlet}\{SidebarColor\}\{red!10!white\}
			\end{Code}
			Modifying a co-varying color in this way changes only that color, leaving the others unaffected.

	\section{Command Line Interface}\label{S:CMD}

		\LaTeX{} does not natively provide a `command line interface' through which a document may be modified at compile time: any change must be made within the source file itself. It is, however, often convenient to compile the same document in several configurations without editing it -- most notably to produce both a standard version and a printer-friendly version (using \texttt{bg = print}, which removes the paper background to reduce ink usage).

		To support this, \rpgtex{} checks for a pseudo command-line variable when processing its options. Because \TeX{} treats the text passed to it on the command line as the beginning of its input stream, this variable can be defined before the document itself is read.

		\RpgVariable{RpgCMD}{
			If defined, holds a comma-separated list of package options \RpgPage[p]{S:PackageOptions}, which are applied after all other options have been processed. The options are applied in the following order, with later values overriding earlier ones:
			\begin{enumerate}
				\item The defaults set by the class (if one is being used).
				\item The options passed in the document, via \cmd{documentclass} or \cmd{usepackage}.
				\item The contents of \cmd{RpgCMD}.
			\end{enumerate}
			Since the options are processed before they are passed to the parent class, options which affect the class (such as \texttt{columns} or \texttt{size}) may also be set in this way.
		}

		\cmd{RpgCMD} is defined by passing a short piece of \TeX{} code to the compiler before the document is input:
		\begin{Code}
			xelatex "\textbackslash{}def\textbackslash{}RpgCMD\{<rpg-options>\} \textbackslash{}input\{<document>\}"
		\end{Code}
		This compiles \texttt{<document>} as though \texttt{<rpg-options>} had been passed to the class or package. For example, the following produces a printer-friendly, single-column version of a document without modifying the source:
		\begin{Code}
			xelatex "\textbackslash{}def\textbackslash{}RpgCMD\{bg=print, columns=1\} \textbackslash{}input\{document.tex\}"
		\end{Code}

		The \texttt{rpglatex} compiler \RpgPage[p]{C:Compiler} performs this insertion automatically: the \texttt{-p} (\texttt{-{}-print}) flag sets \texttt{bg=print}, allowing the user to switch between the standard and print versions of a document with a single flag:
		\begin{Code}
			rpglatex document.tex -p
		\end{Code}
