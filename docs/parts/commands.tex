	\section{Themes \& Colours}\label{S:ThemeSelection}

		\RpgFunction{RpgSetTheme}{\param{name}}
		{
			Loads the theme called \texttt{name}, replacing the appearance of any previously loaded theme. The theme is first searched for at \texttt{<themepath>/<name>/<name>.cfg}; if no such file exists, \texttt{name} is instead treated as a direct path to a theme file. An error is raised if neither file exists.

			The initial theme is set by the \texttt{theme} option \RpgPage[p]{S:PackageOptions}. \cmd{RpgSetTheme} may be called at any point in the document, but since its effects are immediate, it is best called at the start of a new page.
		}
		\RpgFunction{RpgSetThemeColor}{\param{colour}}
		{
			Sets \texttt{ThemeColor} and all of the co-varying colours to \texttt{colour} \RpgPage[p]{S:Colors}.
		}
		\RpgFunction{RpgSetThemePath}{\param{path}}
		{
			Sets the directory searched by \cmd{RpgSetTheme}, allowing custom themes to be stored outside of the \rpgtex{} installation. The path is not checked until a theme is loaded. The initial value is set by the \texttt{themepath} option \RpgPage[p]{S:ThemePath}.
		}

	\section{Document Structure}\label{S:DocStructure}

		\rpgtex{} extends the standard \LaTeX{} commands for structuring a document. It provides title and part pages designed by the active theme, records the names of the current headings so that they may be reused elsewhere, and allows `fake' headings to be added to the table of contents.

		\begin{RpgSidebar}{The Title \& Sections Options}
			Much of the behaviour described in this section is provided by redefining standard \LaTeX{} commands, and is controlled by two package options \RpgPage[p]{S:PackageOptions}. Both are active by default when using one of the \rpgtex{} classes; otherwise, they must be passed to the package explicitly.
			\begin{description}
				\item[\texttt{title}] Redefines \cmd{maketitle} to produce the title designed by the active theme (equivalent to calling \cmd{RpgMakeTitle}). Otherwise, \cmd{maketitle} retains its original \LaTeX{} behaviour.
				\item[\texttt{sections}] Activates \emph{sections mode}, which:
				      \begin{itemize}
					      \item Redefines \cmd{chaptermark}, \cmd{sectionmark}, \cmd{subsectionmark} and \cmd{subsubsectionmark} so that, in addition to their usual behaviour, they store the name they are given \RpgPage[p]{S:SectionNames}.
					      \item Sets \texttt{secnumdepth} to \texttt{0}, so that sections and their subdivisions are unnumbered.
					      \item Replaces \cmd{part} with a version which records the part name and draws a full-page part page using the active theme. The starred form, \cmd{part*}, records the name but otherwise falls back to the original \LaTeX{} command.
				      \end{itemize}
				      Themes may additionally alter the formatting of the sectioning commands when sections mode is active.
			\end{description}
			All of the other commands in this section, including \cmd{RpgMakeTitle}, are available regardless of these options, although the stored heading names are only updated in sections mode.
		\end{RpgSidebar}

		\subsection{Title Pages}\label{S:TitlePages}

			The title page draws on the usual \cmd{title} and \cmd{author} commands, along with the following additions.

			\RpgFunction{cover}{\param{path/to/image}}
			{
				Sets an image to be used as the full-page background of the cover page created by \cmd{maketitle} in \texttt{cover} mode (see below). The theme's title design is drawn over the top of the image.

				The default value is empty, in which case the title design is drawn on a plain page.
			}
			\RpgFunction{maketitle}[RpgMakeTitle]{\param{}}
			{
				Creates the title of the document using the design provided by the theme (only when the \texttt{title} option is active; see above). There are two title modes:
				\begin{description}
					\item[\texttt{cover}] A full-page cover, drawn over the \cmd{cover} image (if one has been set). This is the default for the \texttt{rpgbook} class.
					\item[\texttt{header}] A title heading placed at the top of the first page of text.
				\end{description}
				The mode is selected with \cmd{RpgThemeTitleMode}\param{cover / header}. If the theme does not define a title for the active mode, the original \LaTeX{} \cmd{maketitle} is used instead.

				\cmd{RpgMakeTitle} is equivalent to \cmd{maketitle}, but remains available even if the \texttt{title} option is not active, or if another package redefines \cmd{maketitle}.

			}
			\RpgFunction{RpgCoverTransparency}{\param{value}}
			{
				Fades the \cmd{cover} image towards white, which can help to keep the title legible over a busy image. The \texttt{value} is the opacity of a white layer placed over the image, between \texttt{0} (the image is unaltered) and \texttt{1} (the image is completely hidden). The default value is \texttt{0}.
			}
			\RpgVariable{RpgGetAuthor}[RpgGetAuthor*]{The author set by \cmd{author}, formatted with the \FontRef{SubTitle} font element. The starred form gives the author as plain text.}
			\RpgVariable{RpgGetSubtitle}[RpgGetSubtitle*]{The subtitle set by \cmd{subtitle}, formatted with the \FontRef{SubTitle} font element. The starred form gives the subtitle as plain text.}
			\RpgVariable{RpgGetTitle}[RpgGetTitle*]{The title set by \cmd{title}, formatted with the \FontRef{Title} font element \RpgPage[p]{C:Fonts}. The starred form gives the title as plain text, without applying the font.}

			\RpgFunction{subtitle}{\param{text}}
			{
				Sets the subtitle of the document. As with \cmd{title} and \cmd{author}, this has no visible effect by itself: the subtitle is displayed by \cmd{maketitle} if the theme includes it. The default value is empty.
			}

		\subsection{Part Pages}

			\RpgFunction{part}{(*)[<image>]\param{name}}
			{
				In sections mode \RpgPage[p]{S:DocStructure}, \cmd{part} is redefined to create a full-page part page using the design provided by the theme. Its behaviour depends on the form used:
				\begin{description}
					\item[{\texttt{\textbackslash{}part\{name\}}}] Adds the part to the table of contents and creates a part page on a plain background, or over the default part image if one has been set with \cmd{RpgDefaultPartImage}.
					\item[{\texttt{\textbackslash{}part[image]\{name\}}}] As above, but uses \texttt{image} as the full-page background.
					\item[{\texttt{\textbackslash{}part*\{name\}}}] Uses the original \cmd{part} command of the underlying class. Any image argument is ignored.
				\end{description}
				In all cases, \texttt{name} is recorded in \cmdref{RpgPartName}.
			}
			\RpgFunction{RpgDefaultPartImage}{\param{path/to/image}}
			{
				Sets an image to be used as the full-page background of every part page which is not given its own image. By default, no image is used.
			}
			\RpgFunction{RpgPartTransparency}{\param{value}}
			{
				Fades all subsequent images set by \cmd{part} image towards white, which can help to keep the text legible over a busy image. The \texttt{value} is the opacity of a white layer placed over the image, between \texttt{0} (the image is unaltered) and \texttt{1} (the image is completely hidden). The default value is \texttt{0}.
			}
		\subsection{Section Names}\label{S:SectionNames}
			Many RPG documents display the name of the current chapter or section outside of the heading itself -- in a running header, a footer, or a decorative page border, for example. To support this, \rpgtex{} records the names of the current part, chapter, section, subsection and subsubsection, so that they may be reused anywhere in the document.

			These names are only recorded in sections mode \RpgPage[p]{S:DocStructure}.


			Each of the following variables is initially blank, and holds its value until the next command of the same level is called: beginning a new chapter does not, for example, reset \cmd{RpgSectionName}.

			\RpgVariable{RpgChapterName}{The name given to the last \cmd{chapter} command, or set by calling \cmd{chaptermark}. Starred chapters (\cmd{chapter*}) do not update this value.}
			\RpgVariable{RpgPartName}{The name given to the last \cmd{part} or \cmd{part*} command.}
			\RpgVariable{RpgSectionName}{The name given to the last \cmd{section} command, or set by calling \cmd{sectionmark}. Starred sections (\cmd{section*}) do not update this value.}
			\RpgVariable{RpgSubsectionName}{The name given to the last \cmd{subsection} command, or set by calling \cmd{subsectionmark}. Starred subsections (\cmd{subsection*}) do not update this value.}
			\RpgVariable{RpgSubsubsectionName}{The name given to the last \cmd{subsubsection} command, or set by calling \cmd{subsubsectionmark}. Starred subsubsections (\cmd{subsubsection*}) do not update this value.}


			\RpgFunction{RpgGetName}{\param{part / chapter / section / subsection / subsubsection}}
			{
				Returns the name stored for the given level (equivalent to the corresponding variable above). Any other input results in an error.

				Since these names (other than that of the part) are taken from the \texttt{mark} commands, they may be set manually, without creating a new heading, by calling the relevant \texttt{mark} command directly.
				\RpgGetExample{section-names}
			}

		\subsection{Fake Sections}

			It can be helpful to be able to integrate common RPG elements (such as full page maps or images) into the document structure. The following command provides a simple interface for spoofing in a section (or part, chapter etc.) into the table of contents, without actually invoking a sectioning command:

			\RpgFunction{RpgFake}{\param{level}\param{name}}
			{
				Mimics the creation of a new heading at the given \texttt{level} without printing a heading in the document. Specifically, it:
				\begin{itemize}
					\item Adds an entry called \texttt{name} to the table of contents at the given level, with a hyperlink anchor at the current position.
					\item Updates the stored name for that level, as if a real heading had been created. For \texttt{chapter} to \texttt{subsubsection} this is done by calling the corresponding \texttt{mark} command, so any running headers are also updated.
				\end{itemize}
				The \texttt{level} must be one of \texttt{part}, \texttt{chapter}, \texttt{section}, \texttt{subsection} or \texttt{subsubsection}. Any other value results in an error.

				\RpgGetExample{fake-section}
			}

	\section{Text Utilities}\label{S:TextStyling}\label{S:Utilities}


		\rpgtex{} provides a number of commands for applying decorative styles to text and transforming it in ways useful for writing in an RPG context.

		Any fonts or styles they apply are those assigned by the theme \RpgPage[p]{C:Fonts}.

		\RpgFunction{RpgContour}{[<options>]\param{text}}
		{
			Typesets \texttt{text} with a coloured outline (contour), using the \texttt{contour} package. The following options are available:
			\begin{RpgTable}{lXl}
				Option & Effect & Default
				\\
				\texttt{inner} & The colour of the text itself. & \texttt{ContourInnerColor} \RpgPage[p]{S:Colors}
				\\
				\texttt{outer} & The colour of the outline. & \texttt{ContourOuterColor}
				\\
				\texttt{style} & Formatting commands (such as \cmd{bfseries} or \cmd{Huge}) applied to the text. & (empty)
			\end{RpgTable}
			Contours cannot automatically linebreak, instead the text is split into lines at each \texttt{\textbackslash\textbackslash}, and each word is contoured individually so that spacing is preserved. As a consequence, formatting commands placed within \texttt{text} may only affect the first word: all formatting should therefore be passed through the \texttt{style} key.

			\RpgGetExample{cmd-contour}
		}
		\RpgFunction{RpgDice}{\param{expression}}
		{
			Parses a dice expression of the form \texttt{<count>d<sides><modifier>} and typesets it in the format defined by the theme. The expression must satisfy the following rules:
			\begin{itemize}
				\item It contains a dice symbol (\texttt{d} or \texttt{D}), immediately followed by the number of sides.
				\item The dice symbol may be preceded by the number of dice. If it is omitted, the theme determines how the expression is displayed.
				\item Anything following the number of sides is treated as the modifier, which may be any numerical expression (such as \texttt{+3*2}). It is evaluated to a single number before being displayed.
			\end{itemize}
			Leading and trailing spaces are ignored. If the expression does not match this form, it is printed unchanged.

			\RpgGetExample{cmd-dice}
		}
		\RpgFunction{RpgDropCap}{[<options>]\param{letter}\param{text}}
		{
			Begins a paragraph with a large decorative initial (a `drop cap'), using the \texttt{lettrine} package. The \texttt{letter} is typeset in the \FontRef{DropCap} font element, and \texttt{text} -- intended to be the remainder of the first line -- in the \FontRef{DropCapAfter} font element.

			The drop cap spans a number of lines set by the theme (four, by default), and is separated from the following text by the length \cmd{RpgDropCapSeparation}, which may be changed with \cmd{setlength}. The optional argument accepts any \texttt{lettrine} options, which override these defaults.


			\RpgGetExample{cmd-drop-cap}
		}
		\RpgFunction{RpgKey}[emph]{\param{text}}
		{
			Typesets \texttt{text} in the \FontRef{Emphasis} font element, giving a consistent appearance to keywords (such as conditions or game terms).

			When the \texttt{font} option is active, and unless the \texttt{noemph} option is passed \RpgPage[p]{S:PackageOptions}, \cmd{emph} is redefined to be an alias of \cmd{RpgKey}. This replaces its usual `context-aware' behaviour (italics within upright text, and vice versa) with the keyword style.

			\RpgGetExample{cmd-emph}
		}

		\RpgFunction{RpgOrdinal}{[<format>]\param{number}}
		{
			Typesets an integer followed by its English ordinal suffix (\texttt{st}, \texttt{nd}, \texttt{rd} or \texttt{th}), correctly handling \texttt{11th}, \texttt{12th} and \texttt{13th}. The optional \texttt{format} is a command applied to the suffix only, such as \cmd{textbf}.

			\RpgGetExample{cmd-ordinal}
		}
		\RpgFunction{RpgPage}{[<style>]\param{label}}
		{
			Typesets `page' followed by the page number of \texttt{label}, optionally enclosed in brackets. The \texttt{style} may be one of \texttt{t} (no brackets; the default), \texttt{p} (parentheses), \texttt{b} (square brackets) or \texttt{c} (curly braces). Any other value encloses the reference in question marks, to make the error easy to spot.

			\RpgGetExample{cmd-page}
		}
		\RpgFunction{RpgPlural}{(*)[<plural>]\param{count}\param{word}}
		{
			Typesets \texttt{count} followed by \texttt{word}, adding an `s' to the word unless \texttt{count} is \texttt{1}. Irregular plurals may be given in the optional argument, which replaces the word whenever \texttt{count} is not \texttt{1}. The starred form omits the count, printing only the word.

			\RpgGetExample{cmd-plural}
		}
		\RpgFunction{RpgSuperOrdinal}{\param{number}}
		{
			Equivalent to \cmd{RpgOrdinal}\texttt{[\textbackslash{}textsuperscript]}\param{number} \RpgPage[p]{Cmd:RpgOrdinal}, automatically applying a superscript style command.

			\RpgGetExample{cmd-super-ordinal}
		}

	\section{Full-Page Images}\label{S:Images}

		We use the \texttt{eso-pic}\index{eso-pic} library for formatting whole-page images and placing content at specific positions on the page.
		\RpgFunction{RpgPut}{[<width>][<format>](<anchor>)\param{x}\param{y}\param{content}}
		{
			Places \texttt{content} at a fixed position on the page, measured from the bottom-left corner. It may only be used within a page overlay, such as the first argument of \cmd{RpgWholePageImage}.

			The content is set in a paragraph of the given \texttt{width} (default: \cmd{linewidth}), with \texttt{format} applied at the start (default: \cmd{centering}).

			The \texttt{anchor} determines which point of the content is placed at (\texttt{x}, \texttt{y}): \texttt{c} (centre; the default), \texttt{t}, \texttt{b}, \texttt{l}, \texttt{r}, or a combination such as \texttt{tl}.
		}
		\RpgFunction{RpgWholePageImage}{[<overlay>]\param{path/to/image}[<fade>]}
		{
			Places an image so that it fills the whole of a new page, clearing the page on either side. This is useful for maps, handouts and illustrations.

			The optional \texttt{overlay} is drawn on top of the image, and may contain any number of \cmd{RpgPut} commands. The final optional argument (given in square brackets, after the path) fades the image towards white, as described for \cmd{RpgCoverTransparency} \RpgPage[p]{S:TitlePages}.
		}

	\section{Switches}\label{S:Switches}

		Switches are named true/false values which can be used to change the content of a document without editing its text. For example, \rpgtex{} uses switches to decide whether secrets are shown, and whether rule environments are displayed as cards. All switches are global: changing a switch affects the whole of the remaining document.

		Switches are designed to act as boolean counterparts to traditional \TeX{} counters, and so have a similar interface.

		The primary use-case for switches in \rpgtex{} is for the `Cardable Environments' % BUG: NEED to ref here when we know where it points
		, allowing the same document to typeset as both inline text, and as a 'playing card module' depending on the value of the associated switch.

		\RpgFunction{RpgIfSwitch}{\param{name}\param{if-on}\param{if-off}}
		{
			Typesets \texttt{if-on} if the switch is on, and \texttt{if-off} otherwise.

		}
		\RpgFunction{RpgNewSwitch}{\param{name}[<value>]}
		{
			Creates a new switch called \texttt{name}, with an initial \texttt{value} (default: \texttt{false}). An error is raised if the switch already exists.
		}
		\RpgFunction{RpgSwitch}{\param{name}\param{value}}
		{
			Sets an existing switch to the chosen value. Accepted input strings are:
			\begin{RpgTable}{lX}
				Boolean State & Input Strings
				\\
				True & on, On, true, True, 1
				\\
				False & off, Off, false, False, 0
			\end{RpgTable}

			Any other value raises an error, as does a switch which does not exist.
		}
		\RpgFunction{RpgToggle}{\param{name}}
		{
			Turns an existing switch on if it is off, and off if it is on.

			\RpgGetExample{cmd-switch}
		}
